# Methodology

Each category has four controls: vulnerable, safe, unknown, and unsupported.
Vulnerable and safe controls form the public accuracy score. Unknown and
unsupported controls test whether higher-assurance products describe their
limits honestly.

Benchmark truth is independent of scanner output. A truth change requires review
based on Node.js, framework, library, or security semantics—not on whether a
particular scanner's score improves. Generated catalogs are derived from locked
truth and checked in CI.

The ordinary product application exercises real Koa routes and real Node/library
boundaries. Controller-owned cases use paired identities, state transitions,
concurrent requests, or a second-service witness. Coordinate applications test
framework discovery, module systems, TypeScript attribution, adapters, and
browser-to-backend correlation without redefining the category denominator.

Qualification requires exact coordinates, complete traffic, zero failed requests,
closed coverage, verified evidence, and independent held-out applications. A zero-
finding scan with incomplete coverage is not a clean result.
